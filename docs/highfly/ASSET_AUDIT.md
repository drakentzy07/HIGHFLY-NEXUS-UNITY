# HIGHFLY NEXUS — Asset & Dependency Audit

## Shipping rule

HIGHFLY only ships content with a clear right to use and distribute. The imported upstream is reference material until each system/asset is explicitly approved and migrated into `Assets/Highfly/`.

## Public SubspaceHunter import

Source: `whx-prog/SubspaceHunter-SAO`.

- MIT-covered original software: candidate for reuse with required copyright/license notice retained.
- Public GitHub import contains scripts and demo scenes but does **not** contain the complete external art UnityPackage described by upstream.
- On `highfly-foundation`, the public upstream content is preserved under `UpstreamReference/` so its optional/missing dependencies cannot break the clean Android build.
- `main` preserves the imported upstream project in its original Unity layout.

## External upstream package

Upstream documents an additional UnityPackage hosted outside GitHub. It may contain original models, UI, animation/VFX content, IP-specific SAO material, and third-party packages. It must be audited before any content is migrated into a shipping HIGHFLY build.

### Explicit reference-only / non-commercial SAO content called out upstream

Do not ship recognizable SAO/IP-specific assets such as:

- Heathcliff
- Gleam Eyes
- Kobold Lord
- Stone Golem
- Man-eating / carnivorous flower
- Nicholas / apostate Nicholas
- Kobold Knight
- SAO boar

This list is not exhaustive. Any recognizable Sword Art Online character, monster, logo, environment, name, audio, or artwork remains reference-only unless separately licensed.

## Third-party dependency rule

Never assume a plugin or asset is cleared because it existed in an upstream project. Examples upstream itself flags for separate review include RootMotion/FinalIK, PuppetMaster, Dynamic Bone, environment packs, weapon packs, VFX packs and animation packs.

For every imported third-party dependency record:

1. Source/vendor.
2. Version.
3. License or purchase status.
4. Commercial-use permission.
5. Redistribution permission.
6. Required attribution/notice.
7. Whether it ships in APK or remains editor-only/reference-only.

## HIGHFLY-owned / clean build domain

The first Android Combat Lab intentionally uses only:

- Unity engine packages already declared in the project.
- HIGHFLY C# code under `Assets/Highfly/`.
- Runtime primitives/materials/UI generated by Unity.

This lets us validate movement, camera, targeting, multi-target attacks, dash, skills and Android controls independently of external art packages.
